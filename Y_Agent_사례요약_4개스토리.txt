Y-Agent 사례요약 — 4개 핵심 스토리

숙련자의 도메인 지식과 분석 Know-how를 결합한 Y-Agent 기반 수율 분석
업무 혁신

1P. 숙련자의 전문성을 조직의 분석 역량으로

① 숙련자 의존의 한계에서 시작된 문제의식

데이터의 분산보다 더 큰 문제는 ‘분석 전문성의 격차’

수율 분석은 단순히 데이터를 조회하는 업무가 아니라, 수율 Trend에서
이상을 감지하고 어떤 Fail을 분석할 것인지 판단한 뒤 Map, Inline,
공정·자재 이력 등 다양한 정보를 연속적으로 연결하며 원인을 좁혀가는
복합적인 판단 업무이다.

기존에는 수율일보, SmartFactory 등 여러 시스템을 오가며 엔지니어가 직접
데이터를 탐색·정리하고 분석을 연결해야 했기 때문에 원인 분석 착수까지
많은 시간과 노력이 필요했다.

그러나 보다 근본적인 한계는 동일한 Fail과 분석 결과를 보더라도 무엇을
먼저 확인하고, 어떻게 해석하며, 다음에 어떤 분석을 수행할 것인지가
엔지니어의 경험과 도메인 지식에 따라 달라진다는 점이었다. 특히 고연차
엔지니어가 오랜 경험을 통해 축적한 분석 방법과 판단 기준을 저연차
엔지니어와 조직 전체가 반복적으로 활용하기에는 한계가 있었다.

이에 단순한 업무 자동화를 넘어, 숙련자의 도메인 지식과 분석 Know-how를
조직 전체가 활용할 수 있는 분석 역량으로 전환하는 것을 Y-Agent의
출발점으로 삼았다.

② 더 높은 목표에 도전 — 숙련자의 판단 과정을 Agent의 분석 역량으로

업무 자동화를 넘어 수율 분석 방식 자체를 재설계

Y-Agent의 목표를 여러 시스템의 데이터를 편리하게 조회하는 수준에 두지
않았다. 숙련자의 도메인 지식과 분석 Know-how에 통계·머신러닝을 결합하고
이를 Agent의 분석 역량으로 구현하여, 경험 수준에 관계없이 전문적인 수율
분석을 활용할 수 있는 새로운 업무체계를 구축하는 것을 목표로 설정하였다.

이를 위해 기존 OPLS의 수율 분석 SOP를 기반으로 수율·PI·개발 엔지니어 등
현업 전문가들과 인터뷰를 진행하였다. 숙련자가 실제 분석에서 무엇을
확인하고, 결과를 어떻게 해석하며, 어떤 후속 분석으로 연결하는지를
구체화하고 다양한 분석 방법을 비교하여 실행 가능한 Agent Logic으로
전환하였다.

이를 수율일보, 이상감지, Map, 불량이력, 자재이력, 연관분석, Mining 등
13개 전문 Agent와 24개 Tool로 구현하고, Super Agent가 분석 목적과 결과에
따라 필요한 Agent를 연결하도록 하였다. 열화감지에는 현업에서 실제
활용하는 Logic을, Mining에는 분류 머신러닝과 Wafer Map 기반 분석을
결합하는 등 범용 AI의 추론에만 의존하지 않고 현업의 전문성을 Agent의
분석 역량에 내재화하였다.

이는 기존 업무를 단순히 자동화한 것이 아니라 숙련자가 수율 문제를
바라보고 분석을 이어가는 과정 자체를 Agent 기반 Workflow로 전환한
도전이었다. 개별 업무 효율화를 넘어 조직의 수율 분석 역량을 높인다는 한
단계 높은 목표를 설정하고 기존 업무 방식의 한계에 도전했다는 점에서
SUPEX 추구와 패기의 의미를 갖는다.

2P. 기술 검증을 넘어 현업 Co-pilot으로, 다시 조직의 지식으로

③ 실제 수율 문제로 검증 — ’동작하는 Agent’에서 ’현업이 사용하는 Agent’로

개발의 완료 기준을 기술 구현이 아닌 현업 문제 해결에 설정

Y-Agent는 기술적으로 Agent가 동작하는 것을 개발의 완료 기준으로 삼지
않았다. 실제 수율 문제를 분석하고 현업 엔지니어의 판단과 후속 업무에
도움이 되는 결과를 제공할 수 있는가를 기준으로 현업 검증을 진행하였다.

실제 수율팀과 Daily 회의를 진행하며 현업 엔지니어가 Y-Agent를 직접
사용하고 분석 결과의 타당성과 업무 활용성을 반복적으로 검증하였다. 실제
수율 이슈 7건 중 5건을 Y-Agent를 통해 검출하였으며, 나머지 2건은 현재
구현되지 않은 분석 방법이 필요한 사례로 확인하여 추가 고도화 영역으로
구체화하였다.

또한 현업 사용자 관점에서 필요한 81개의 Action Item을 도출하여 기능과
분석 방법을 지속적으로 개선하였다. 현재는 일부 수율팀 엔지니어가
Y-Agent를 직접 사용하며 실제 수율 점검과 Issue 분석에 활용하는 Co-pilot
단계로 발전하였다.

즉, 개발자가 만든 AI를 현업에 전달하는 방식이 아니라 실제 사용 → 현업
검증 → 개선 요구 도출 → Agent 고도화 → 재검증의 반복 과정을 통해 기술
검증을 실제 업무 활용으로 연결하였다.

④ 개인의 경험을 조직의 지식으로 — 지속 진화하는 Autonomous Agent로

현업에서 새롭게 만들어지는 분석 경험까지 다시 Agent의 역량으로 축적

Y-Agent의 최종 목표는 현재의 Co-pilot 구축에서 끝나지 않는다. 앞으로
실제 엔지니어가 Y-Agent를 사용하면서 어떤 Fail을 어떤 Sequence로
분석했는지, 어떤 결과를 확인하고 어떤 Action을 수행했는지, 당시 Wafer
CumMap은 어떠했는지를 Workflow 지식으로 축적할 계획이다.

고연차 엔지니어들의 다양한 분석 Workflow와 Action 경험을 LLM Wiki에
지식화하여, 유사한 Fail이 발생하면 과거의 분석 방법과 대응 경험을
Agent가 참조·추천하도록 발전시키고자 한다.

이를 통해 Co-pilot → Workflow 지식화 → Knowledge 기반 Agent → Autonomous
Yield Analysis Agent로 단계적으로 발전시키고, 궁극적으로는 Fail 열화와
분석 결과를 기반으로 필요한 분석을 수행하고 후속 Action까지 추천하는
체계를 지향한다.

동시에 그룹 내 Y-Agent 활용을 확대하고, 구축한 MCP를 사내 MCP Market으로
확장하여 전사 횡전개 기반을 마련하고자 한다.

숙련자의 기존 경험을 Agent의 역량으로 전환하는 데서 출발하여, 현업에서
새롭게 생성되는 경험까지 다시 조직의 지식으로 축적함으로써 ’사용할수록
전문성이 강화되는 수율 분석 체계’를 구축하는 것이 Y-Agent가 지향하는
궁극적인 변화이다.
